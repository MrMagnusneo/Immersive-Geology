# Immersive Geology NeoForge 1.21.1 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port all Immersive Geology content and behavior from Forge 1.20.1 to NeoForge 1.21.1, produce a verified gameplay JAR, and open a PR into `neoforge-1.21.1`.

**Architecture:** Preserve the current material-driven content model and registry IDs. Migrate bottom-up: establish a machine-readable baseline, replace the build/bootstrap layer, port common platform APIs, then IE recipes/multiblocks, worldgen, client/integrations, and finally validate the packaged mod against the baseline.

**Tech Stack:** Java 21, Gradle wrapper, NeoForge ModDevGradle 2.x, Minecraft 1.21.1, Immersive Engineering 1.21.1, JUnit 5, NeoForge game tests, Python 3 content audit.

## Global Constraints

- `forge-1.20.1` remains unchanged; canonical target is `neoforge-1.21.1`; implementation branch is `codex/neoforge-1.21.1-port`.
- Initial core platform matrix is Java 21, Minecraft `1.21.1`, NeoForge `21.1.234`, Immersive Engineering `1.21.1-12.4.2-194`, JEI `19.27.0.343`, and Parchment `2024.11.17`, matching the sibling Technology port; change a pin only when resolution or API compatibility proves it necessary and record the replacement.
- All registry IDs, material definitions, 18+ multiblock families, recipes, worldgen, assets, generated data, translations, integrations, and configuration keys must be preserved or mapped one-to-one.
- No content removal, disabled registration, no-op implementation, or compile-only stub is acceptable.
- Optional integrations remain optional and may not classload when their dependency is absent.
- Full clean build must pass three times and the dedicated server must reach normal startup.
