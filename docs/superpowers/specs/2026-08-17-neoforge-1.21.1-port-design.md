# Immersive Geology NeoForge 1.21.1 Port Design

## Goal

Port the complete `forge-1.20.1` mod to Minecraft 1.21.1 and NeoForge, produce a verified gameplay JAR, and submit the port through a pull request without removing or stubbing content.

## Branch strategy

- Create `neoforge-1.21.1` from the current `forge-1.20.1` head as the canonical target branch.
- Develop the port on `codex/neoforge-1.21.1-port` and open the pull request into `neoforge-1.21.1`.
- Keep `forge-1.20.1` unchanged so the existing release line remains buildable and reviewable.

## Build and platform migration

- Replace ForgeGradle and Forge metadata with NeoForge ModDevGradle and `META-INF/neoforge.mods.toml`.
- Use Java 21, Minecraft 1.21.1, a compatible NeoForge release, and the matching Immersive Engineering 1.21.1 API/artifacts.
- Replace Forge-specific dependency configurations and optional integration artifacts with NeoForge 1.21.1 equivalents. An integration stays optional when it was optional in the source branch.

## Code migration

- Port mod bootstrap, deferred registrations, event subscriptions, configuration, networking payloads, capabilities or data attachments, menus, screens, rendering, client setup, world generation, recipes, loot, tags, data generation, and game tests to the 1.21.1 NeoForge APIs.
- Port the complete Immersive Engineering integration, including multiblock definitions, machine state and ticking, energy/fluid/item handlers, recipes, manual content, model callbacks, and rendering.
- Preserve registry identifiers and serialized data formats whenever the 1.21.1 platform permits it so existing worlds and datapacks have the best practical migration path.
- Do not delete features, suppress registrations, or replace implementations with no-op placeholders to obtain a successful build.

## Content-completeness audit

- Generate a baseline manifest from `forge-1.20.1` containing registered blocks, items, fluids, block entities, entity types, menus, recipe serializers/types, multiblocks, sounds, and configuration keys.
- Compare all source assets and data categories: textures, models, blockstates, languages, sounds, recipes, tags, loot tables, worldgen, Patchouli/manual data, shaders, and generated resources.
- Require every baseline identifier or resource to be present on the NeoForge branch, or document a one-to-one 1.21.1 replacement. Unexplained omissions fail validation.

## Validation

- Add focused automated checks for the content manifest, JSON/resource validity, metadata, and build invariants before changing production behavior.
- Run unit tests, validated data generation, and a dedicated-server startup smoke test that reaches normal server initialization without registry or datapack errors.
- Run a clean full Gradle build three times and inspect each gameplay JAR for metadata, entry points, mixins, assets, and data.
- Record any behavior that cannot be exercised headlessly as a manual in-game verification checklist; compilation alone is not accepted as proof of a complete port.

## Deliverables

- Gameplay JAR for Minecraft 1.21.1 / NeoForge.
- Canonical `neoforge-1.21.1` branch and source changes on `codex/neoforge-1.21.1-port`.
- Pull request into `neoforge-1.21.1` containing build, test, datagen, server-smoke, and content-audit evidence.
